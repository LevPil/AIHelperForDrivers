# AIHelperForDrivers

Виртуальный ассистент на основе больших языковых моделей (LLM) для помощи водителям и ученикам автошкол в вопросах Правил дорожного движения Российской Федерации.

Основная идея проекта - дать возможность быстро получить точный ответ по ПДД в текстовом или голосовом формате, опираясь на актуальную нормативную базу.

## Основные возможности

- Текстовый режим: вопросы по теории ПДД с поиском по нормативной базе
- Голосовой режим: распознавание речи -> ответ -> синтез речи
- Поддержка контекста диалога
- Переключение между локальной моделью и облачной
- Классификация вредоносных/нецелевых запросов
- Микросервисная архитектура с контейнеризацией

## Архитектура

Система разделена на два основных сервиса:

- **Java (Spring Boot)** - веб-интерфейс, аутентификация, управление сессиями, маршрутизация запросов
- **Python (FastAPI / Uvicorn)** - вся логика работы с LLM, RAG, агентами и речью

Связь между сервисами происходит по HTTP (JSON-контракт). Всё развёртывается через Docker Compose.

## Технологический стек и зачем каждая технология

### Backend (Java)
- **Java + Spring Boot** - основной бэкенд приложения. Выбран за надёжность, удобную работу с REST API, безопасность и возможность быстро собрать веб-приложение с шаблонами.
- **Thymeleaf** - серверный шаблонизатор для генерации HTML-страниц интерфейса чата.
- **Maven** - управление зависимостями и сборка проекта.
- **PostgreSQL** - реляционная база данных для хранения пользователей и истории диалогов.
- **Redis** - in-memory хранилище. Используется для быстрого кэширования сессий и краткого резюме диалога (чтобы модель «помнила» контекст без хранения всей истории целиком).

### Сервис ИИ (Python)
- **Python** - основной язык для работы с моделями и данными.
- **LangChain** - фреймворк для построения цепочек и агентов на базе LLM. Позволяет удобно управлять промптами, историей диалога и вызовами инструментов.
- **Uvicorn** - ASGI-сервер для запуска Python-сервиса.
- **ChromaDB** - векторная база данных. Хранит эмбеддинги фрагментов ПДД. Нужна для реализации RAG.
- **Ollama** - инструмент для локального запуска больших языковых моделей. Позволяет работать без интернета.
- **Qwen 2.5-7B** - локальная модель (через Ollama). Хорошо работает с русским языком и относительно легко запускается на обычном железе.
- **GigaChat API** - облачная модель от Сбера. Используется как альтернатива локальной модели, когда нужна более высокая качество ответа.
- **SaluteSpeech API** - сервис от Сбера для распознавания речи (STT) и синтеза речи (TTS). Обеспечивает голосовой режим работы ассистента.
- **Hugging Face / эмбеддинги** - для преобразования текстов ПДД в векторы (модель используется: nomic-embed-text).

### Инфраструктура
- **Docker + Docker Compose** - контейнеризация всех сервисов (Java, Python, Redis, Ollama и т.д.). Позволяет поднять весь проект одной командой на любой машине.
- **RAG** - запрос пользователя ищется в векторной базе фрагментов ПДД, найденные куски добавляются в промпт, и модель отвечает, опираясь на реальные правила.

### Доп.
- **Логистическая регрессия** - классическая модель машинного обучения для классификации вредоносных/нецелевых запросов (защита от нецелевого использования ассистента).
- **TF-IDF + scikit-learn** - для векторизации текста и обучения классификатора безопасности.

## Как это работает

1. Пользователь отправляет текстовый или голосовой запрос.
2. Если запрос голосовой - он распознаётся через SaluteSpeech.
3. Запрос проверяется классификатором на безопасность.
4. Через RAG в ChromaDB ищутся релевантные фрагменты ПДД.
5. Найденный контекст + вопрос + краткое резюме предыдущего диалога (из Redis) отправляются в LLM (локальную или облачную).
6. Ответ возвращается пользователю. Если был голосовой режим - ответ синтезируется в аудио.
7. Краткое резюме диалога обновляется в Redis.
